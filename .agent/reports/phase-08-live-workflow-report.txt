same placement count, same roles, same start/end frames, same placement ids, no duplicates.

deliberately excluded from the comparison.

5. ONE OPERATIONAL FINDING
--------------------------

The first `apply-preview` attempt of this session was **killed by a 2-minute command timeout**
at item 16 of 40. The executor is transactional against *failures*, not against its own process
being killed, so it could not roll back: it left a well-formed partial preview
(`DAZ_AUTO_PREVIEW_20260817_232757_635443b7`, 16 items, 15 owned and 1 inserted-but-not-yet-
tagged). No protected timeline was touched, and the partial output was internally consistent
with the plan up to the point of the kill.

It was disposed of by exact name — the same `MediaPool.DeleteTimelines` call the executor makes
itself on a normal failure — and the run repeated cleanly. Recorded because the timing matters
for whoever runs this next: on this material `apply-preview` and `rebuild-preview` each take
**four to six minutes** (voice render + VAD + 40 insertions, each with a marker write and a
verifying re-read). Do not run them under a short timeout.
