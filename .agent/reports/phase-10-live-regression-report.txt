3. THE ONLY DIFFERENCES, AND WHY EACH IS EXPECTED
----------------------------------------------------

    a) diagnostics.role_counts loses six keys that were always 0:
         face_x1_to_gameplay, face_x2_to_gameplay, face_x3_to_gameplay,
         gameplay_to_face_x1, gameplay_to_x0, x0_to_gameplay
       The dictionary is keyed by the configured roles; six roles no longer exist.
       No count changed.

    b) PlanSource.assets / .asset_transition_frames / .asset_identities lose their
       six gameplay entries. This is a real change to the plan's IDENTITY, and it is
       the documented consequence of the retirement (D068): a plan computed before
       Phase 10 is no longer field-for-field equal to one computed after it, so
       `rebuild-preview` against a pre-Phase-10 preview would recompute rather than
       match on those fields.

       No compatibility layer was added, on purpose. Faking an identity to make an
       old plan acceptable is exactly the class of convenience this project refuses
       (safety > convenience). What matters is that the EDITORIAL result and the
       per-clip `placement_id` are unchanged: `placement_id` hashes the source
       fingerprint, the role, the frames and the asset name — none of which moved —
       so every existing facecam preview stays recognisable, ownable and cleanable.
       There is a test for that (`tests/test_ownership.py`).

    c) the trace's asset-inventory line, as noted in section 2.

Nothing else differs. `diff` over the full extracted plan (356 lines: totals,
diagnostics, identity, segments, bursts, every placement, every valley, the whole
decision trace) shows those three regions and no other.
